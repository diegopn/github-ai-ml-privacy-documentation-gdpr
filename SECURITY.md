# Política de segurança

## Versões cobertas

Este repositório não publica releases numeradas. A branch `main` é a linha atualmente considerada para correções; commits anteriores não têm manutenção garantida.

## Como relatar uma vulnerabilidade

Use o [formulário privado de relato de vulnerabilidade do GitHub](https://github.com/diegopn/github-ai-ml-privacy-documentation-gdpr/security/advisories/new), se estiver habilitado. Não publique detalhes exploráveis em issues, discussions, pull requests ou comentários.

Se o formulário privado estiver indisponível, abra uma issue apenas para pedir um canal privado. Não inclua detalhes técnicos, credenciais, dados pessoais, amostras de documentos coletados, logs ou código de prova de conceito nessa issue.

No relato privado, informe, quando relevante, o arquivo ou commit afetado, passos mínimos de reprodução, impacto provável e mensagens de erro. Remova `GITHUB_TOKEN`, outros segredos, dados pessoais e conteúdo desnecessário de logs e exemplos.

Teste somente contas, dados e sistemas para os quais você tem autorização. Não acesse dados de outras pessoas nem interrompa serviços.

## Escopo

Esta política cobre o pipeline R de seleção, coleta histórica e análise, a integração com a API do GitHub, os artefatos e relatórios gerados, além dos workflows e da página Quarto mantidos neste repositório. Vulnerabilidades na plataforma GitHub ou nos repositórios de terceiros estudados devem ser encaminhadas aos respectivos mantenedores; falhas neste projeto ao selecionar, coletar ou processar essas informações permanecem no escopo.

Os artefatos podem conter conteúdo de repositórios e usuários públicos. Ao relatar um problema, compartilhe somente o material necessário e remova identificadores e dados que não sejam essenciais.

Os relatos são analisados conforme a disponibilidade do mantenedor. Não há prazo garantido de resposta ou correção; quando possível, a divulgação pública será coordenada após uma correção.
